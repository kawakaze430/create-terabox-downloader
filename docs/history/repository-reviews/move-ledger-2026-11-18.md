## Source and reuse review

- **TeraPlayer** uses FastAPI, async MongoDB clients, HTTP clients and auth libraries. Its React frontend uses player, routing, UI and ZIP libraries, with a postbuild prerender script. The client contains separate folder selection, extraction and download status, and HLS/video UI. Reviewed these as patterns for truthful state, responsive file selection, and cancellation. None is necessary to implement the current frontend. Backend modules include admin/account/auth, diagnostics, scheduling, user-facing extension jobs, caches and several third-party network extraction paths. The archived MV3 extension declares `storage`, `tabs`, 17 host permission patterns and two content-script entries. It has a substantially broader access profile than the current active extension. The archive also contains an external worker, cron/webhook shell scripts, hidden agent instructions and editor configuration. Their presence does not put them on the active app’s execution or CI paths. Avoid adopting archived session handling, automation, provider logic or broad permissions.
- **Gateway** uses Flask/Werkzeug and aiohttp with a setuptools package. It contains an optional publishing workflow with OIDC token permissions, service/CLI entrypoints, a TTL cache, rate limiter, retry helpers, and provider/worker and cookie configuration. TTL expiration, bounded retries, and clear failure mapping are useful general patterns. The active engine already owns retry budgets and egress controls. The archived external worker, cookie configuration, proxy routes and publishing workflow have no role in that engine or in the active CI.
- Both archive roots carry MIT licenses. TeraPlayer also includes an Apache-licensed agent helper within its tree. Assess licenses and dependencies per file before reusing any source and retain required notices. This review recommends no extraction or source reuse for the current milestone. No third-party code was copied.
